# Remote Desktop WEB

Форк [rezapace/rdp-local](https://github.com/rezapace/rdp-local) — спасибо автору за основу проекта.

Браузерный удалённый рабочий стол: шаринг экрана через WebRTC, удалённое управление мышью/клавиатурой через RobotJS, WS-релей как запасной транспорт. Полностью автономно — без внешних CDN и STUN по умолчанию.

## Возможности

- Шаринг экрана (WebRTC, кодеки VP9/VP8/H264)
- Удалённое управление: мышь, клики, колесо, клавиатура, тач
- Список хостов по IP у клиента (`IP (ID: N)`), пометка `view only`
- Автоматический WS-релей видео (MJPEG), если WebRTC заблокирован в браузере
- Авто-HTTPS с самоподписанным сертом для работы по LAN-IP
- `config.ini`: порт, интерфейс, логи, SSL
- Скриншот, запись, PiP, полноэкранный режим, статистика соединения

## Требования

- Node.js 14+
- Для управления: Windows/macOS/Linux с рабочим RobotJS (ставится через `npm install`)
- Хост открывает страницу по `localhost` или `https://` (требование браузера для захвата экрана)

## Быстрый старт

```cmd
npm install
npm start
```

Или готовый бинарник: `dist/remote-desktop.exe` (при первом старте рядом создаются `config.ini` и `ssl/`).

Сборка exe:

```cmd
build-exe.cmd
```

## config.ini

```ini
[server]
port = 9000          ; порт
host = 0.0.0.0       ; 0.0.0.0 = все интерфейсы; конкретный IP = только он
                     ; (этот же адрес попадёт в баннер и в автосерт)
verbose = 0          ; 1 = подробные логи (WS, ICE, HTTP, клавиши)

[ssl]
key = ssl/key.pem
cert = ssl/cert.pem
no_auto = 0          ; 1 = без автогенерации, чистый HTTP (шаринг только via localhost)
```

Приоритет: переменные окружения (`PORT`, `HOST`, `SSL_KEY`, `SSL_CERT`, `SSL_NO_AUTO`, `VERBOSE`, `CONFIG`) → `config.ini` → дефолты.

## HTTPS и LAN

Захват экрана работает только в secure context. Варианты для хоста:

1. Открыть `http://localhost:9000` на самой машине хоста (вьюеры — по LAN-IP, им это не нужно).
2. HTTPS: при старте сервер сам генерирует `ssl/key.pem` + `ssl/cert.pem` (CN/SAN под адрес из `host`) — открыть `https://<ip>:9000` и один раз принять предупреждение браузера.

## Топология управления — важно

RobotJS двигает курсор **машины, где запущен сервер**. Поэтому для управления хостом сервер (`node server.js` / exe) должен работать **на самом хосте**. Если целевой хост — другая машина, сервер пропустит ввод и пришлёт вьюеру `control-unavailable`, а кнопка управления станет неактивной (в списке такой хост помечен `view only`).

## Транспорты видео

1. **WebRTC** (основной, P2P). По умолчанию только LAN host-кандидаты, без внешних серверов. Для интернета: `?stun=1` (или `localStorage.rdpStun=1`) включает Google STUN; свой TURN — `?turn=user:pass@host:port` или `localStorage turnUrl/turnUser/turnCred`.
2. **WS-релей** (автоматический фолбэк): если ICE не встаёт за ~8 сек (в браузере вообще нет кандидатов — фаервол/VPN/политики), хост шлёт JPEG-кадры (~5 fps) через WebSocket. Управление при этом работает как обычно.

## Диагностика

- В консоли браузера: `app.testIceGathering()` (0 кандидатов = WebRTC задушен в окружении), `app.diagnoseBlackScreen()`, `app.diagnoseOverlay()` (геометрия канваса/видео).
- Подробные логи клиента: `?debug=1` или `localStorage.rdpVerbose=1`; сервера: `verbose = 1`.
- Сервер предупреждает о двух вьюерах, шлющих мышь одновременно (закрыть дубликаты вкладок).

## Устранение неполадок

| Симптом | Причина / действие |
|---|---|
| `getDisplayMedia` / `mediaDevices` undefined у хоста | Открыт plain HTTP по LAN-IP → хосту открыть `localhost` или включить HTTPS |
| Чёрный экран, `ice=new` навсегда | WebRTC заблокирован → включится WS-релей сам; для P2P чинить окружение |
| Курсор дёргается, клики не доходят | Второй вьюер/вкладка шлёт ввод (см. варнинг сервера); очередь чинится сама |
| `control-unavailable` | Сервер не на хосте → перенести exe на хост |
| Сервер не останавливается по Ctrl+C | Исправлено: graceful shutdown с добивкой сокетов; повторный Ctrl+C — мгновенный выход |

## Структура проекта

```
.
├── server.js          # HTTP(S) + WebSocket-сигналинг + RobotJS-ввод
├── index.html         # UI + клиентская логика (inline, внешних запросов нет)
├── config.ini         # настройки сервера (создаётся шаблон при первом старте exe)
├── package.json       # ws, robotjs, selfsigned; pkg-сборка в dist/
├── build-exe.cmd      # сборка portable exe
└── dist/              # готовый remote-desktop.exe
```

Зависимости: `ws`, `robotjs`, `selfsigned` (+ dev: `nodemon`, `pkg`). Всё остальное в `node_modules` — транзитивное, в git не трекается (`npm ci` для восстановления).
